# 리프맵 LeafMap — 부산 채식 메뉴 성분 확인 웹 대시보드

AI데이터기반서비스기획 중간과제 · 2023761031 이다운

부산을 찾는 외국인 채식 여행자가 **식당 이름이 아니라 메뉴의 재료·육수·양념 제품 성분 근거**를 보고 메뉴를 고를 수 있도록 돕는 서비스의 MVP 웹 시제품입니다. 기획서의 모바일 앱 구상을 설치 없이 링크로 여는 **웹 대시보드**로 바꿨습니다.

## 사이트 구성
| 파일 | 대상 | 내용 |
|---|---|---|
| `index.html` | 여행자·식당 사장님 | **모바일 앱 형식의 여행자 서비스 + 사장님 앱.** 화면은 라인 아이콘 세트로 통일, 식당 카드에 음식 종류 썸네일과 ‘영업 중’ 표시, 처음 쓰는 이용 고객에게 3장짜리 사용 안내(더보기에서 다시 보기), 식당 상세는 핵심 버튼 3개(길찾기·한국어 카드·성분 확인 요청)와 접는 구역으로 정리. 로그인에서 ‘이용 고객 / 식당 사장님’을 고름. **사장님 앱**(한국어 기본): 리프맵의 실제 식당 108곳 중 내 가게를 골라 ① 내 가게(성분 확인 요청·리뷰·제보 수, 요청 손님 식단, 메뉴 등록 진행 상태, 손님에게 보이는 정보, 정보 수정 요청) ② 메뉴 등록(메뉴마다 5단계: 기본 정보 → 구성 재료 → 양념 제품 **성분표 사진 AI 분석**(원재료를 하나씩 나눠 식물성·동물성·확인 필요로 분류, 사장님이 수정) → 조리 방식 → 식단별 판정 초안) ③ 손님 요청(확인 요청·리뷰·제보) ④ 요금·광고(무료/스탠다드 월 9,900원/프로 월 19,900원, **첫 달 무료**, 지도 추천 핀·검색 상단·식단 맞춤 광고 신청 — 가격은 가설, 실제 결제 없음). 운영자가 광고를 승인하면 여행자 화면에 ‘광고’ 표시와 함께 노출. 이용 고객은 로고 스플래시 → 시연용 로그인(닉네임·식단, 게스트 가능) → 카카오맵 스타일 **실제 지도** 홈(카카오맵, 안 되면 OpenStreetMap·CARTO, 묶음 핀, 내 위치, 바텀시트, 카카오맵 길찾기). **기본 화면은 영어**이고 검색바의 키로 한국어 전환. 식당은 **부산 전역에서 채식 메뉴가 하나라도 있는 실제 식당 108곳**(HappyCow 공개 목록, 2026년 11월 확인)을 메뉴 중심(채식 메뉴 이름·평점)으로 보여 주며 메뉴 성분은 ‘리프맵 확인 전’으로 표시. 식당마다 리뷰(리프맵 이용자 별점·후기 작성, 카카오맵·HappyCow 리뷰 링크). **메뉴판 AI 읽기**: 한국어 메뉴판을 찍으면 브라우저 안 AI 글자 인식(Tesseract.js)으로 읽고, 메뉴 이름을 영어로 옮기고 내 식단 기준으로 주의할 재료를 표시(AI 초안). 식당마다 **성분 확인 요청** 버튼, 한국어 카드에 **상황별 문장·음성 읽기**. 하단 탭(지도·찾기·**AI 메뉴판**·더보기, AI 메뉴판 탭 = 메뉴판 사진 읽기 + 그 아래 한국어 카드), 휴대폰에선 화면 전체, PC에선 가운데 폰 프레임+QR로 표시. 식단(비건·락토오보·페스코·돼지고기·술 안 먹어요·소고기 안 먹어요·직접 설정)·제외 재료 설정(바텀시트) — 지도 위 식단 키를 누르면 그 식단에 맞는 식당만 지도·목록에 표시(공개 정보 기준: 비건은 비건 메뉴가 있는 곳만, 술을 안 먹으면 펍·양조장·와인 바 제외, 메뉴 전부가 식단에 맞는 곳을 맨 위에 ‘메뉴 전부 OK’로 표시), 메뉴/식당/지도 보기, 검색, 메뉴 상세(성분표 원문·AI 해석·식당 확인 상태), 직원에게 보여주는 한국어 카드(전체 화면), 정정 제보, 사장님 등록 신청, 한/영 전환 |
| `dashboard.html` | 운영자 | 운영 대시보드(PC용 웹 화면). 앱의 **더보기 → 운영자 대시보드**, 또는 PC 화면 왼쪽 버튼으로만 들어갑니다. **실제 식당 수요** 화면에서 여행자 앱의 성분 확인 요청·리뷰·정보 제보를 모아 확인 우선순위와 다음 할 일을 추천합니다 |

- 두 페이지는 같은 Supabase 프로젝트를 씁니다. 웹사이트에서 보낸 **정정 제보**는 `reports`에 저장되고 해당 메뉴가 ‘추가 확인 필요’로 바뀌며, **사장님 등록 신청**은 `submissions`에 저장됩니다. 둘 다 대시보드(정정 제보·등록·검토 큐)와 활동 기록에 나타납니다.
- 메뉴·식당 상세는 `#menu/m1`, `#place/r1` 주소를 가져서 링크 공유와 브라우저 뒤로가기가 됩니다.
- 식단·언어 같은 개인 설정은 각자 브라우저에만 저장됩니다.
- Supabase에 연결하지 못하면 내장 예시 데이터를 보여 주고, 제보·신청은 막아 둡니다.

## 판정 규칙
- **제외 재료 포함**: 사용자의 제외 재료 중 하나라도 사용한 것으로 확인
- **추가 확인 필요**: 제품 불명, 식당 사용 확인 대기, 상충 제보
- **조건에 맞음**: 제외 재료를 대조할 근거가 있고 식당 사용 확인 완료

## 실행
빌드 없이 `index.html`(여행자 앱)과 `dashboard.html`(대시보드) 두 파일로 동작합니다. 브라우저로 열거나 GitHub Pages로 배포하세요.

## 데이터 저장 (Supabase)
식당·메뉴, 정정 제보, 신규 등록 자료, 운영 활동 기록은 Supabase(PostgreSQL)에 저장해 누가 접속해도 같은 데이터를 봅니다. 언어·식단 필터 같은 개인 설정은 각자의 브라우저에만 저장됩니다.

1. Supabase에서 새 프로젝트를 만듭니다 (Region: Seoul).
2. SQL Editor에 `supabase/setup.sql`을 붙여넣고 Run 합니다.
3. Project Settings → API Keys에서 Project URL과 Publishable key(`sb_publishable_…`)를 복사해 `index.html`과 `dashboard.html`의 `SUPABASE_URL`, `SUPABASE_KEY`에 넣습니다.
4. 사이트를 처음 열면 시연용 초기 데이터가 테이블에 자동으로 채워집니다. 사이드바 아래에 ‘● Supabase 연결됨’이 보이면 성공입니다.

두 값을 비워 두면 예전처럼 브라우저(localStorage)에만 저장됩니다. 시연용이라 로그인 없이 누구나 데이터를 바꿀 수 있게 열어 두었습니다.

## 유의 사항
식당·메뉴·제품·제보·운영 기록은 모두 시연용 가상 데이터입니다. 목표 수치·일정·수익 금액은 검증 전 가설입니다. Supabase를 연결하지 않으면 버튼으로 바꾼 상태는 브라우저 localStorage에만 저장됩니다. 사이드바의 ‘데모 데이터 초기화’로 처음 상태로 되돌릴 수 있습니다(Supabase 연결 시 테이블도 함께 초기화).
